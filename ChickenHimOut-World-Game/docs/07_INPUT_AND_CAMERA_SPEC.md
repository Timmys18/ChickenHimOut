# Input and Camera Specification

**Status:** DRAFT — Gate 01  
**Target:** mobile landscape, one-hand capable

## 1. Input Principle

Сложность находится в причинных связях мира, а не в количестве кнопок. Базовый игровой цикл должен управляться одним пальцем. Второй палец не требуется для успешного прохождения кампании.

## 2. Core Touch Vocabulary

### Tap

Контекстное действие с минимальной неоднозначностью:

- выбрать тактическую позицию;
- активировать доступный переключатель;
- подтвердить контекстный переход;
- ускорить result sequence.

### Press and Drag

Главный жест галстука:

1. касание героя или активного конца галстука;
2. протягивание к допустимому anchor;
3. preview линии, направления и напряжения;
4. отпускание для Attach/Commit.

### Drag While Attached

После прикрепления:

- изменить силу натяжения;
- выбрать направление тяги;
- провести галстук через routing point;
- удержать объект в нестабильном состоянии.

### Release

Отпустить связь в выбранный момент. Release является самостоятельным игровым решением, а не только окончанием жеста.

### Swipe to Position

Короткий свайп в сторону подсвеченной позиции разрешает быстрый контекстный переход героя во время эскалации или побега.

## 3. No Permanent Virtual Joystick

Постоянный joystick запрещён как базовый input. Он создаёт пустую ходьбу, усложняет камеру и размывает идентичность игры.

Герой перемещается между authored Tactical Position Nodes. Позиции должны:

- быть визуально читаемыми без постоянных маркеров;
- находиться на расстоянии 0.4–1.5 секунды анимации;
- менять доступные anchors и угол воздействия;
- иметь понятную цену риска;
- поддерживать аварийный переход во время хаоса.

## 4. Anchor Acquisition

Чтобы touch-control не ощущался неточным:

- anchor имеет увеличенную невидимую touch-zone;
- используется screen-space magnetism;
- preview меняет форму и звук при попадании в допустимую зону;
- при нескольких соседних anchors приоритет определяется механическим смыслом и направлением drag;
- длительное удержание открывает короткий radial choice только при реальной неоднозначности;
- мелкие декоративные объекты не конкурируют с mission-critical anchors.

## 5. Interaction States

`Observe → Acquire → Preview → Attach → Tension → Commit → Dynamic Control → Reattach/Release → Escape`

В каждый момент игра должна ясно показывать:

- чем игрок сейчас управляет;
- что произойдёт при отпускании;
- насколько действие рискованно;
- можно ли отменить действие.

## 6. Cancel and Recovery

- drag обратно к герою отменяет preview;
- короткий tap по пустой безопасной области отменяет незакоммиченное действие;
- после ошибочного attach даётся короткое recovery window, если катастрофа ещё не началась;
- после Commit отмены нет: игрок управляет последствиями.

## 7. Camera Philosophy

Камера — режиссёр, а не отдельная механика. Игрок не обязан вручную вращать или масштабировать сцену.

Основной формат — 2.5D side-three-quarter view с ограниченной глубиной действия. Мир полноценный 3D, но композиция контролируется.

## 8. Camera Modes

### Establishing

Короткий входной кадр 1.5–3 секунды:

- показывает цель;
- демонстрирует основную работающую систему;
- заканчивается на стартовой позиции героя.

### Tactical

Основной кадр:

- герой и текущая цель находятся в safe composition zones;
- видны минимум две потенциальные связи;
- глубина читается через параллакс, перекрытия и свет;
- camera rail ограничивает угол, но допускает плавное смещение.

### Tension Focus

При натяжении камера слегка приближается и смещается вдоль вектора силы. Масштаб изменения ограничен, чтобы не потерять контекст.

### Chaos Director

После Commit камера выбирает наиболее значимое событие через Director Priority System. Она не прыгает на каждый мелкий объект.

Приоритет:

1. угроза герою;
2. mission-critical state change;
3. редкая цепная реакция;
4. крупное разрушение;
5. выразительная NPC reaction;
6. вторичные детали.

### Escape

Камера расширяет кадр и заранее показывает возможные escape anchors. Во время быстрого перехода применяется controlled lead, а не свободное следование.

### Result

Короткая композиция финального состояния сцены, затем hero beat и UI результата.

## 9. Camera Constraints

- никаких резких поворотов более 35° во время активного touch-drag;
- target anchor не должен уходить за пределы safe area в процессе preview;
- camera movement прекращается за 100–150 мс до точного release window;
- depth-of-field используется только в постановочных beat, не во время точного управления;
- screen shake масштабируется по событию и имеет accessibility toggle;
- slow motion не более 0.6–1.2 секунды и только для редких значимых моментов.

## 10. Readability Layer

Подсказки являются частью мира, а не россыпью UI:

- лёгкий material pulse у доступного anchor;
- реакция галстука на допустимую цель;
- направление силы через изгиб и натяжение;
- локальные частицы пыли/скрипа у перегруженного соединения;
- NPC смотрят на критическую точку;
- звук механизма предупреждает о смене состояния.

Яркие outline используются только как fallback accessibility mode.

## 11. Haptics

- лёгкий tick при входе в anchor zone;
- нарастающий vibration curve при tension;
- короткий удар при Commit;
- отдельный pattern при imminent failure;
- все haptics отключаемы.

## 12. Prototype Acceptance Tests

- 8 из 10 новых игроков выполняют первый Hook без объяснения после одной визуальной демонстрации;
- ошибочный выбор соседнего anchor — менее 10% попыток;
- игрок понимает preview результата до release;
- камера не скрывает mission-critical event;
- ни один обязательный шаг не требует второго пальца;
- переход между Tactical Position занимает менее 1.5 секунды;
- игрок может назвать причину провала сразу после fail beat.
