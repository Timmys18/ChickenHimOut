## 2. Что строим

Название: **ChickenHimOut**.

Формат: сатирическая мобильная игра с короткими миссиями.

Главная механика: длинный красный галстук используется как физический инструмент — зацепить, потянуть, связать объекты, вызвать цепную реакцию, затем красиво сбежать.

Первая миссия: **«Стена»**.

Игровой ритм:

1. Игрок находит точку зацепа.
2. Тянет галстук и меняет связи между объектами.
3. Мир отвечает и начинает разваливаться управляемым образом.
4. Игрок делает ещё несколько вмешательств.
5. Получает ложное ощущение победы.
6. Успевает сбежать.
7. Видит результат и причину пройти миссию ещё раз.

Целевая длительность прохождения: 25–40 секунд.

## 3. Зафиксированные продуктовые решения

- Мобильная горизонтальная ориентация.
- iOS и Android — основные платформы.
- Управление касанием и перетягиванием, без постоянного виртуального джойстика.
- Первая миссия должна иметь не менее трёх разных способов прохождения.
- Итог оценивается по четырём параметрам:
  - выполнение цели;
  - масштаб хаоса;
  - стиль;
  - побочный ущерб.
- Нужен мгновенный повтор без возврата в меню.
- Подсказки должны появляться только когда игрок застрял.
- Не использовать навязчивые механики удержания, наказание за отсутствие, плату за победу и другие тёмные приёмы.
- Никаких реальных имён, портретного сходства, названий реальных премий или прямого копирования публичного лица.

## 4. Зафиксированная техническая база

Версия Unity:

`6000.5.4f1`

Основные решения:

- URP.
- Render Graph обязателен.
- 60 кадров в секунду — основной ориентир.
- Физика игрового мира обновляется 60 раз в секунду.
- Unity Input System + Enhanced Touch.
- Cinemachine 3.
- UI Toolkit для нормального интерфейса; временный экран прототипа сейчас сделан проще.
- Burst + Jobs для тяжёлых вычислений.
- Обычные игровые объекты и PhysX остаются основой критической механики.
- Addressables и Localization заложены с начала проекта.

## 7. Известные проблемы и риски

### 7.1. Возможные ошибки пространств имён

Код создавался несколькими крупными пакетами. В проекте встречаются пространства имён вида:

- `ChickenHimOut.Game.*`
- `ChickenHimOut.WorldGame.*`
- `ChickenHimOut.Interaction`
- `ChickenHimOut.Tie`

Первое действие Claude: открыть проект и устранить все несовпадения пространств имён и ссылок между сборками.

### 7.2. Ранее было два дерева проекта

Часть файлов сначала оказалась вне правильного Unity-корня. Большинство дублей удалено, но нужно ещё раз проверить, что вне:

`ChickenHimOut-World-Game/game/ChickenHimOut/`

не осталось активного кода или старых настроек, которые могут путать сборку.

### 7.3. Сцена создаётся автоматически, но соединение компонентов не доказано

Файл:

`Assets/Game/Editor/WallGreyboxSceneBuilder.cs`

Он создаёт тестовую сцену, но нужно проверить:

- назначены ли камера, герой и начало галстука;
- назначена ли маска точек зацепа;
- присвоены ли роли точкам зацепа;
- соединены ли кран, панель, противовес и грузовик;
- есть ли полноценный путь до победы и поражения;
- появляется ли выход для побега.

### 7.4. Экран прототипа временный

Текущий экран результата сделан через простой встроенный интерфейс Unity. Это допустимо только для проверки механики. Для визуального этапа его нужно заменить нормальным мобильным интерфейсом.

### 7.5. Звук и вибрация пока базовые

Система есть, но реальные звуковые файлы могут быть не назначены. Вибрация пока использует общий вызов устройства, а не финальные нативные шаблоны.

### 7.6. Автоматическая сборка не запускалась

GitHub Actions настроен, но сборки не было из-за отсутствия подключённой Unity-лицензии в секретах репозитория.

## 8. Первый обязательный план Claude

Не добавлять новые функции, пока не пройден этот порядок.

### Шаг 1. Получить проект локально

Переключиться на:

`gate/02-mechanical-prototype`

Открыть:

`ChickenHimOut-World-Game/game/ChickenHimOut/`

в Unity `6000.5.4f1`.

### Шаг 2. Добиться чистого открытия

- дождаться импорта пакетов;
- исправить все ошибки компиляции;
- не подавлять ошибки временными заглушками;
- удалить или привести к единому виду несовпадающие пространства имён;
- проверить сборки `.asmdef`.

Результат шага: ноль красных ошибок в Console.

### Шаг 3. Создать тестовую сцену

Запустить пункт меню:

`ChickenHimOut / Build Wall Greybox Scene`

Проверить, что сцена создаётся и сохраняется.

### Шаг 4. Сделать миссию реально проходимой

Минимальный рабочий путь:

1. игрок цепляется галстуком;
2. действие запускает реакцию крана или панели;
3. игрок выбирает вторую точку;
4. возникает опасность;
5. открывается возможность побега;
6. игрок достигает выхода;
7. появляется экран результата;
8. кнопка повтора перезапускает миссию менее чем за 1,5 секунды.

### Шаг 5. Добавить аварийный режим проверки

Нужна простая клавиатурная проверка в редакторе, чтобы без телефона можно было:

- зацепить основные объекты;
- принудительно перейти к следующему этапу;
- вызвать победу;
- вызвать поражение;
- повторить сцену.

Это ускорит поиск ошибок, но не должно заменять мобильное управление.

### Шаг 6. Собрать Android-файл

После чистого запуска:

- установить Android Build Support, SDK, NDK и OpenJDK через Unity Hub;
- собрать Development APK;
- сохранить файл как артефакт GitHub или приложить к релизу;
- зафиксировать точную версию сборки и commit SHA.

### Шаг 7. Проверить на реальном телефоне

Минимальная проверка:

- установка проходит;
- приложение запускается;
- экран не переворачивается;
- касание и перетягивание работают;
- нет вылета за три полных прохождения;
- повтор запускается быстро;
- звук и вибрация не зависают;
- частота кадров не падает катастрофически.

## 9. Критерий состояния «ставь на телефон и играй»

Начинать следует именно с этого, а не с добавления новых документов или функций.
